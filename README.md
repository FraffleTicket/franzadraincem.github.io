# Franz Christian A. Adraincem — Portfolio Website

## 1. What this is

A static, self-contained personal portfolio website for Franz Christian A. Adraincem —
Healthcare Virtual Assistant | Administrative & Operations Support | Social Media & Graphic
Design. It's plain HTML, CSS, and JavaScript — no framework, no build step, no backend
server. It covers: hero intro, about, experience, services, a filterable creative/social
media portfolio with a project modal, skills, tools & technology (with brand-colored icons),
education & certifications, workflow, a short personal section, and contact.

There is **no backend contact form** — the Contact section uses direct `mailto:` and `tel:`
links plus a LinkedIn link, since a static site has nowhere to send form submissions without
a third-party form service. If you want a working contact form later, see "Adding a contact
form" near the end of this file.

## 2. Folder structure

```

│
├── index.html                  Main page — all sections live here
├── css/
│   └── style.css                All styling: layout, colors, typography, animations, responsive rules
├── js/
│   └── main.js                  All behavior: mobile nav, scroll reveal, portfolio filter/modal, tool & service rendering
├── assets/

│   ├── icons/                   Reserved for custom icon files (currently empty — see assets/icons/README.txt)
│   └── logos/
│       └── fca-logo.png         The "FCA" logo used in the top navigation bar
├── fonts/
│   └── README.txt               Explains font loading (Google Fonts CDN) + how to self-host fonts for full offline use
├── favicon/
│   └── favicon.svg              Browser tab icon
```

This is a flat, plain-HTML structure on purpose — no `src/`, no `node_modules/`, no build
output folder — because that's all a static site like this needs, and it keeps GitHub Pages
deployment (see section 9) as simple as uploading the folder as-is.

## 3. Running it locally

No installation and no build step required.

**Simplest way:** double-click `index.html` to open it directly in your browser.

Everything works this way *except* that opening a raw `file://` page can occasionally cause
your browser to block or warn about local image loading, depending on browser settings. If
you see any image not loading when opened this way, use a tiny local server instead (also
simple):

- **VS Code**: install the "Live Server" extension, right-click `index.html`, choose
  "Open with Live Server."
- **Python** (if installed): open a terminal in the `my-portfolio` folder and run:
  ```
  python -m http.server 8000
  ```
  then visit `http://localhost:8000` in your browser.

## 4. Editing text content

Almost everything visible on the page is plain text inside `index.html`. Open it in VS Code
and search for the section you want to change — each section is wrapped in an HTML comment
like `<!-- ================= ABOUT ================= -->` to make them easy to find:

- **Hero headline/subtext**: inside `<section class="hero" id="top">`
- **About Me story**: inside `<section id="about">`
- **Experience / timeline entries**: inside `<section id="experience">`
- **Education & certifications**: inside `<section id="education">`
- **Contact info (email, phone, LinkedIn)**: inside `<section id="contact">` — search for
  `mailto:`, `tel:`, and `linkedin.com`

A few sections are generated by JavaScript from data arrays in `js/main.js` instead of being
written directly in the HTML (this makes them easier to extend):

- **Services** — the `services` array near the top of `js/main.js`
- **Creative portfolio projects** — the `projects` array (see section 8 below)
- **Tools & Technology** — the `toolsHands` and `toolsLearning` arrays

To edit any of these, open `js/main.js`, find the array, and change the text inside the
matching object's fields.

## 5. Replacing images

All images live in `assets/images/`, `assets/logos/`, and `favicon/`. To swap one out:

1. Add your new image file into the right folder (keep a similar file size — a few hundred
   KB max per image keeps the site fast).
2. If you're replacing an existing file (e.g. `profile-photo.jpg`) with a same-named file,
   you don't need to change any code — just overwrite it.
3. If you use a **different filename**, update the matching reference:
   - Profile photo: `<img src="assets/images/profile-photo.jpg" ...>` in `index.html`
     (inside the Hero section).
   - Nav logo: `<img src="assets/logos/fca-logo.png" ...>` in `index.html` (inside `<header>`).
   - Favicon: the `<link rel="icon" href="favicon/favicon.svg">` line in `index.html`'s
     `<head>` (note: the current favicon is a vector `.svg`; if you replace it with a `.png`
     or `.ico`, update this href to match).
   - Portfolio project images: the `image:'assets/images/...'` field for that project in the
     `projects` array in `js/main.js` (see section 8).

## 8. Adding portfolio projects

Open `js/main.js` and find the `projects` array (it has a comment block above it explaining
the same thing). Each project is one JavaScript object:

```javascript
{
  title:'Your Project Title',
  category:'social',              // must match a key in the categories array just above
  catLabel:'Social Media Designs', // the label shown on the card
  role:'Graphic Designer',
  tools:['Canva'],
  desc:'A short, honest description of the project.',
  image:'assets/images/project-08-your-new-project.jpg'
}
```

To add a new project:
1. Drop your image file into `assets/images/` (a clear name like
   `project-08-your-new-project.jpg` is recommended so files stay easy to track).
2. Copy an existing object in the `projects` array, paste it as a new entry, and edit its
   fields.
3. `category` must be one of: `social`, `graphic`, `promo`, `business`, `content` (these
   power the filter buttons above the grid — see the `categories` array right above
   `projects` if you want to add a new filter category).

No other code changes are needed — the grid, filter buttons, and click-to-expand modal all
render automatically from this array.

## 9. Uploading to GitHub

1. Create a new repository on GitHub (e.g. `my-portfolio`).
2. From inside the `my-portfolio` folder on your computer, run:
   ```
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<your-username>/my-portfolio.git
   git push -u origin main
   ```
   (Replace `<your-username>` with your GitHub username. If you don't have Git installed,
   you can instead use GitHub's website: create the repo, then use "Add file → Upload files"
   and drag in the entire folder contents.)

## 10. Enabling GitHub Pages

1. In your repository on GitHub, go to **Settings → Pages**.
2. Under "Build and deployment," set **Source** to "Deploy from a branch."
3. Choose the `main` branch and the `/ (root)` folder, then click **Save**.
4. GitHub will publish your site at `https://<your-username>.github.io/my-portfolio/` within
   a minute or two — refresh the Pages settings screen to get the exact link once it's live.

No build step, no Node.js, and no configuration file is needed for this — it's a plain
static site, which is exactly what GitHub Pages is built to serve.

### Alternative: Netlify (also free, drag-and-drop)
1. Go to [app.netlify.com](https://app.netlify.com) and sign in.
2. Click **Add new site → Deploy manually**.
3. Drag the whole `my-portfolio` folder onto the upload area.
4. Netlify gives you a live URL instantly (e.g. `random-name.netlify.app`).

## 11. Connecting a custom domain later

**On GitHub Pages:**
1. Buy a domain from any registrar (Namecheap, Google Domains, etc.).
2. In the registrar's DNS settings, add a `CNAME` record pointing your domain (or subdomain,
   e.g. `www`) to `<your-username>.github.io`.
3. In your repo's **Settings → Pages**, enter your custom domain in the "Custom domain" field
   and save. GitHub will auto-generate a `CNAME` file in your repo — don't delete it.
4. Wait for DNS to propagate (can take up to 24 hours) and optionally enable "Enforce HTTPS"
   once GitHub shows the certificate as ready.

**On Netlify:** go to **Site settings → Domain management → Add a custom domain** and follow
Netlify's prompts — it will tell you exactly which DNS records to add at your registrar.

## External dependencies

The only external resource this site loads is a Google Fonts stylesheet link in
`index.html`'s `<head>` (for the Sora and Inter typefaces). Nothing else — no JavaScript
libraries, no icon library, no CSS framework, no analytics, no tracking scripts. See
`fonts/README.txt` if you want to remove even that dependency and self-host the fonts for
fully offline use.

## Adding a contact form

Since GitHub Pages / Netlify (as static hosts) can't run server-side code, a real working
contact form needs a third-party form backend. Two simple, free-tier options if you want to
add one later:
- [Formspree](https://formspree.io) — add `action="https://formspree.io/f/YOUR_ID"` to a
  `<form>` and it emails submissions to you, no server code needed.
- [Netlify Forms](https://docs.netlify.com/manage/forms/setup/) — if you deploy on Netlify,
  add a `data-netlify="true"` attribute to a `<form>` and Netlify handles submissions
  automatically.

Either would slot into the existing Contact section without needing any other changes to the
site.
